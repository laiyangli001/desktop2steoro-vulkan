# Desktop2Stereo Flet GUI2 重设计实施计划

## 1. 文档状态与结论

- **状态**：设计与实施计划，尚未修改 GUI 代码。
- **日期**：2026-08-30。
- **目标运行库**：项目当前固定的 `flet==0.86.5`。
- **最终选择**：采用方案 B 的渐进式版本，即“顶部菜单栏 + 左侧功能导航 + 中央内容区 + 固定底部操作栏”。
- **隔离原则**：`src/desktop2stereo/gui/` 中的原 GUI 文件保持不变；全部新界面代码放入 `src/desktop2stereo/gui2/`。
- **回退原则**：原 GUI 继续作为默认入口。GUI2 先通过独立入口试运行，验收通过后才允许切换发布默认值；任何 GUI2 故障都可立即改用原 GUI。

本计划只重构控制面，不修改立体算法、模型、捕捉、Vulkan、OpenXR、串流运行时，也不新增或迁移 `settings.yaml` 字段。

## 2. 当前界面评估

### 2.1 主要问题

1. 现有界面将大量低频、高频参数放在同一连续表单中，首次使用者难以判断必要设置和高级设置。
2. 语言和主题作为独立设置行，占用主操作区域，但它们属于全局应用设置，应该进入菜单。
3. 运行、停止、状态、日志和参数编辑处于同一视觉层级，主任务不够突出。
4. 当前布局以固定宽度和窗口自动适配为主；参数继续增加后，横向拥挤和低分辨率溢出风险会扩大。
5. `GUIBuilderMixin` 同时承担控件创建、分组、窗口尺寸计算和页面装配，后续新增菜单或页面容易继续扩大单一构建模块。
6. 现有配置、事件和进程生命周期已经较完整，直接重写业务逻辑风险高；重构应优先“复用控件和逻辑，替换信息架构与装配方式”。

### 2.2 方案判断

不选择只增加菜单栏的方案 A。方案 A 改动较小，但无法解决参数密度、功能扩展和日志占用空间的问题。

GUI2 采用方案 B，但按阶段落地：

1. 先建立与原 GUI 功能等价的独立 GUI2 包。
2. 再将现有控件重新分组到六个页面，不改变配置键和运行逻辑。
3. 最后加入菜单、社区入口、响应式布局和视觉统一。

这种顺序把业务兼容性和视觉重构分开，任何阶段失败都不影响原 GUI。

### 3.3 响应式规则

- 逻辑宽度 `>= 1040`：左侧导航展开并显示图标与文字，内容区允许双列卡片。
- 逻辑宽度 `760～1039`：导航收窄，内容区按卡片最小宽度自动换行。
- 逻辑宽度 `< 760`：导航只显示图标和 tooltip，内容区强制单列，底部按钮使用紧凑宽度。
- 窗口最小逻辑尺寸建议为 `680×480`；低高度下只滚动中央内容，不滚动顶部菜单和底部操作栏。
- 所有尺寸继续通过现有 `S()` 缩放函数适配 DPI，不自行替代 Windows 系统 DPI 缩放。
- `NavigationRail.scrollable=True`，确保六个入口在低高度窗口中仍可访问。

## 4. 信息架构与页面职责

### 4.1 首页 / 运行

只呈现完成一次运行所需的核心设置：

- 输入类型、输入显示器或窗口、刷新输入源。
- 运行模式、立体输出设备、显示适配。
- 当前模型摘要、计算设备摘要和目标帧率摘要。
- 当前配置有效性、运行状态、后端状态和阻塞性错误。

首页摘要只反映其他页面的当前值，不创建第二套配置字段。

### 4.2 立体参数

- 深度模型、模型规格、深度分辨率。
- 立体预设、质量、视差预算、会聚和深度强度。
- 时间稳定、场景重置、补洞、边缘处理和前中后景参数。
- 颜色调整作为可折叠的“画面颜色”卡片保留在本页。

高频参数默认展开；专业参数使用 `ExpansionTile` 或等价折叠容器，默认折叠但保持配置加载和保存。

### 4.3 性能设置

- 计算设备、捕捉工具、捕捉帧率和垂直同步。
- FP16、TensorRT、`torch.compile`、并行推理。
- NVIDIA Frame Generation / NvFRUC 及其状态。
- 渲染尺寸策略、缩放、对齐和像素上限。

能力不支持的选项继续使用现有禁用或回退逻辑，不在 GUI2 中重新判断硬件能力。

### 4.4 串流与 XR

- Local Viewer、3D Monitor、OpenXR、MJPEG、RTMP 的模式相关参数。
- XR 头显、控制器、环境、显示模式。
- 串流协议、地址、质量、码率、音频、校准和实际活动后端。

页面根据现有运行模式动态显示对应卡片，继续复用当前 `_get_streamer_row_map()` 和可见性语义。

### 4.5 高级设置

- 投影 LOD、MIP Bias、RCAS 和低频画质参数。
- 调试、实验性功能和不适合普通用户直接调整的参数。
- 未来配置导入/导出、模型管理和更新检查的页面入口预留。

预留只体现在注册结构，不显示没有实现的空白按钮或不可用菜单。

### 4.6 日志与诊断

- 完整运行日志、日志级别和清空/复制操作。
- 后端状态、最近错误和诊断摘要。
- “工具 → 日志与诊断”直接导航到该页面。

现有日志队列、状态解析和进程生命周期不变，只调整展示容器。

## 5. 顶部菜单设计

Flet 0.86.5 已提供 `MenuBar`、`SubmenuButton` 和 `MenuItemButton`。GUI2 使用声明式菜单注册表构建菜单，菜单项至少包含稳定 ID、国际化键、图标、回调、启用条件、可见条件和子项；未来增加功能时不直接修改根布局。

```text

│  └─ 简体中文
├─ 主题
```

## 6. QQ 群、官网和关于对话框

### 6.1 集中配置

GUI2 新增独立社区配置模块，集中定义：

```python
WEBSITE_URL = "https://d2s.site"
QQ_GROUP_NUMBER = None
QQ_INVITE_URL = None
QQ_QR_ASSET = None
```

当前仓库没有 QQ 群号、邀请链接和二维码资源，因此首版不得生成或猜测这些值。

后续提供素材后，二维码放入：

```text
src/desktop2stereo/gui2/assets/community/qq-group.png
```

GUI2 启动时通过 `ft.run(..., assets_dir=...)` 注册资源目录，二维码使用 `ft.Image` 显示，并提供加载失败的 `error_content`。

### 6.2 QQ 交流群对话框

使用 `AlertDialog`，内容固定为：

- 标题和简短说明。
- 二维码或“二维码暂未提供”的空状态。
- 群号；缺失时显示“群号暂未提供”。
- “复制群号”按钮；群号缺失时禁用。
- “打开邀请链接”按钮；邀请链接缺失时禁用。
- 关闭按钮。

复制优先使用 Flet 0.86.5 的 `Clipboard` 服务；失败时显示本地化 `SnackBar`，不得无提示失败。

### 6.3 外部链接和关于

- 官网和邀请链接通过 `page.launch_url()` 打开。
- URL 必须来自集中配置，不接受用户输入，不执行 shell 拼接。
- 打开失败时显示中英文错误提示并保留可复制 URL。
- “关于”对话框显示应用名、当前 `VERSION`、官网和版权/开源信息，不重复硬编码版本号。

## 7. GUI2 代码隔离与目录结构

### 7.1 不可修改边界

实施期间禁止修改：

```text
src/desktop2stereo/gui/**
src/desktop2stereo/settings.yaml
```

原 GUI 的 Python 文件、Flet 包、客户端缓存和行为均保持原样。

### 7.2 新目录

```text
src/desktop2stereo/gui2/
├─ __init__.py
├─ __main__.py
├─ gui.py                    GUI2 应用与入口
├─ builders.py               页面控件、卡片和根布局
├─ handlers.py               菜单、导航、对话框及 UI 事件
├─ localization.py           GUI2 完整中英文文本
├─ controls.py               GUI2 视觉组件和响应式辅助
├─ config_mgr.py             与原配置字段等价的加载/保存
├─ process.py                与原运行/停止生命周期等价
├─ paths.py                  GUI2 资源路径；运行数据仍指向公共目录
├─ menu_registry.py          声明式菜单结构
├─ community.py              官网、QQ 群和资源配置
└─ assets/community/         社区图片资源
```

### 7.3 复制与复用策略

- 首版 GUI2 使用 `Desktop2StereoGUI` 作为兼容性生命周期外壳，仅在 GUI2 中覆盖页面装配、菜单、导航、对话框、窗口边界和日志页路由；原 GUI 文件保持不变。
- 这样可以继续复用已经验证的配置、设备探测、进程启动/停止、日志队列和运行模式动态逻辑，同时把新视觉层隔离在 `gui2/`。
- GUI2 不复制大型 `flet_packages/` 和 `flet_clients/`；Flet 客户端准备逻辑和只读安装包/缓存继续由原 GUI 路径提供。
- 后续若需要消除继承耦合，应先把稳定的运行/配置协议迁移到公共模块，再独立拆分 GUI2；首版不扩大业务重构范围。

## 8. 启动、切换与回退

### 8.1 并行验证阶段

- 保留现有 `--gui` 和默认行为，继续启动原 GUI。
- 在原 GUI 目录之外，为 `app_runtime/bootstrap.py` 增加 `--gui2`，仅显式传入时导入 `gui2.gui.main`。
- GUI2 同时支持模块入口，便于独立调试。

建议命令：

```powershell
# 原 GUI，始终可用
src\python3\python.exe src\desktop2stereo\main.py --gui

# 新 GUI2，独立试运行
src\python3\python.exe src\desktop2stereo\main.py --gui2
```

### 8.2 发布切换阶段

GUI2 完成自动化和实机验收后，启动器可在原 GUI 目录之外读取 `D2S_GUI_VARIANT=gui|gui2`：

- 未设置或值无效：启动原 GUI，并记录一次警告。
- `gui`：启动原 GUI。
- `gui2`：启动 GUI2。
- 显式 `--gui` / `--gui2` 的优先级高于环境变量。

回退只需改回 `D2S_GUI_VARIANT=gui` 或使用 `--gui`，不删除文件、不迁移配置、不还原提交。

### 8.3 配置并发边界

GUI1 与 GUI2 使用同一份 `settings.yaml`，不得同时运行并编辑配置。GUI2 不新增配置锁协议；继续沿用现有单实例/启动器边界，并在测试说明中明确禁止双开。

## 9. 配置与运行逻辑兼容

1. GUI2 读取和保存现有全部配置键，不改变类型、默认值、显示值到内部值的映射或本地化映射。
2. 所有原有控件对象都必须在 GUI2 中创建；页面切换只重新挂载或切换容器可见性，不能因控件暂时不可见而丢失配置。
3. `apply_config()`、配置收集、热参数保存、运行模式切换和动态能力禁用必须保持等价。
4. GUI2 继续启动相同 Runtime 子进程、传递相同环境和配置快照，不修改 Runtime 接口。
5. 运行中不允许切换 GUI 版本；必须先停止 Runtime 并关闭当前 GUI。
6. 恢复默认设置继续使用现有动态默认值逻辑，并在菜单操作前增加确认对话框。

## 10. 视觉与交互规范

- 采用紧凑桌面工具风格，基础间距使用 `8`，卡片内边距使用 `12～16`，圆角使用 `8`。
- 颜色来自当前 Flet Theme；只为成功、警告、错误和运行按钮使用语义色，不硬编码整套浅色/深色背景。
- 页面标题、卡片标题、标签和辅助文字形成四级层次，避免所有文字同字号同权重。
- “运行”为主要 Filled 操作，“停止”为高辨识度次要操作，“恢复默认”为低强调操作。
- 运行、停止按钮和状态摘要固定在底部操作栏；页面滚动时仍可操作。
- 有阻塞性错误时禁用运行按钮，并在底部状态区显示简短原因；详细信息进入日志诊断页。
- 菜单、导航、卡片标题、对话框、tooltip、空状态、错误提示全部具有 EN/CN 文本。
- 键盘 Tab 顺序按“菜单 → 导航 → 当前页面 → 底部操作”排列；菜单和按钮保留 tooltip 与语义标签。
- 参考 Flet Studio Gallery 的视觉组织方式，但只采用项目 Flet 0.86.5 本地实测存在的控件和属性。

## 11. 分阶段实施

### 阶段 0：建立基线

- 记录原 GUI 目录文件清单和哈希，运行现有 GUI 相关测试。
- 建立当前配置的往返快照和原 GUI 启动/运行/停止基线。
- 创建 GUI2 包和独立入口，不改变默认启动路径。

完成标准：GUI2 初始副本可启动；原 GUI 目录无差异；原测试保持通过。

### 阶段 1：页面化但保持功能等价

- 在 GUI2 中保留全部原控件和事件逻辑。
- 建立六页导航和页面容器，将现有控件按本计划重新装配。
- 固定底部运行控制栏，日志迁入日志诊断页。
- 保持所有运行模式的动态显示和配置保存。

完成标准：原 GUI 与 GUI2 对同一配置产生等价 Runtime 配置；所有原功能均有可访问入口。

### 阶段 2：菜单与社区入口

- 移除 GUI2 主内容中的语言/主题专用行。
- 新增设置、工具、帮助菜单和声明式注册表。
- 新增官网、QQ 交流群、关于对话框及错误处理。
- 增加 GUI2 国际化文本和当前选中状态。

完成标准：语言、主题和默认设置行为与原 GUI 等价；官网和社区入口按有/无素材两种状态工作。

### 阶段 3：响应式与视觉统一

- 加入三个宽度档位、导航收缩、卡片换行和单列布局。
- 统一间距、标题、按钮、状态和错误视觉。
- 调整窗口自动适配逻辑，避免页面切换时窗口反复跳动。

完成标准：`680×480`、`960×600`、`1280×720` 和 4K 高 DPI 下均能访问全部关键操作，无横向内容丢失。

### 阶段 4：切换能力与发布验收

- 增加 `--gui2` 和可选环境变量选择，不改变 `--gui`。
- 完成 Windows、Linux、macOS 启动冒烟测试。
- 验收通过后才允许发布配置默认选择 GUI2。
- 更新 `changelog.md`，只记录最终用户可见结果和架构里程碑。

## 12. 自动化测试计划

### 12.1 隔离和入口

- 测试 `src/desktop2stereo/gui/` 在实施提交中没有修改。
- `--gui` 导入原 GUI，`--gui2` 导入 GUI2。
- 环境变量和显式参数优先级符合第 8 节。
- GUI2 导入失败时，启动器给出明确错误；发布回退流程仍可显式启动原 GUI。

### 12.2 菜单、国际化和社区

- 菜单结构、稳定 ID 和子菜单顺序正确。
- English / 简体中文切换后，菜单、导航、页面和对话框同步刷新。
- 九种主题值与现有内部值保持一致，重启后恢复。
- 官网固定为 `https://d2s.site`。
- QQ 素材缺失时显示空状态，复制和邀请按钮禁用。
- QQ 素材存在时显示二维码，可复制群号并打开邀请链接。
- URL 打开、剪贴板和图片加载失败时显示本地化错误。

### 12.3 配置和运行等价

- 使用代表性 EN/CN 配置执行 GUI1 与 GUI2 配置往返对比。
- 覆盖 Local Viewer、3D Monitor、OpenXR、MJPEG、RTMP 模式。
- 覆盖显示器/窗口选择、动态控件可见性、设备能力禁用和默认值恢复。
- 覆盖运行、取消启动、停止、ESC、关闭窗口和子进程异常。
- 验证隐藏页中的控件值不会被默认值覆盖。

### 12.4 布局

- 对三种宽度档位验证导航状态、卡片列数、内容滚动和底部操作栏固定。
- 低高度时六个导航入口仍可滚动访问。
- 日志显示/隐藏或页面切换不会导致窗口尺寸持续抖动。
- 浅色、深色和系统主题下文本、边框、选中态和错误态可读。

## 14. 验收标准

- 原 `gui/` 目录零修改，原 GUI 可继续启动和运行。
- GUI2 全部代码位于 `gui2/`，只有启动选择、测试、文档和 changelog 可修改其他目录。
- GUI2 覆盖原 GUI 全部可用配置和运行能力，不改变 `settings.yaml` schema。
- 语言和主题不再占用 GUI2 主参数行，且保存、重启恢复正常。
- 顶部菜单可扩展，无空白占位功能；官网、QQ 和关于入口行为完整。
- 运行、停止、状态和错误在任何页面及支持的窗口尺寸下可见。
- 自动化测试、`py_compile`、`git diff --check` 和三平台启动冒烟通过。
- 回退不需要还原文件或迁移配置，只需选择原 GUI 入口。
