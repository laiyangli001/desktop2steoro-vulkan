# 自动网络与性能校准使用说明

本文说明如何在 Desktop2Stereo Vulkan 中使用“自动网络与性能校准”，为电脑发送端与 Pico、Quest 等头显浏览器之间的 WebRTC 串流选择稳定的帧率和码率。

## 1. 功能用途

自动校准会运行一次真实的端到端串流测试，测试路径包括：

```mermaid
flowchart LR
    A[电脑画面采集] --> B[立体画面生成]
    B --> C[FFmpeg 编码]
    C --> D[MediaMTX / WebRTC]
    D --> E[局域网]
    E --> F[头显浏览器解码]
    F --> G[统计数据回传]
    G --> H[自动选择稳定档位]
```

校准不是单独测试网卡带宽，而是同时检查电脑处理性能、编码速度、局域网传输和头显浏览器解码能力。完成后，程序会自动保存并应用推荐的 FPS、目标码率和峰值码率。

该功能适用于“高级网络推流”和“GPU 推流”模式，仅支持 WebRTC；不适用于 MJPEG、本地预览或 OpenXR Link。两种网络模式共享同一套端到端校准控制器，但测试时仍使用各自的实际视频编码后端。

## 2. 使用前准备

开始校准前确认：

- 电脑与头显连接到同一个局域网。
- GUI 中的运行模式选择“高级网络推流”或“GPU 推流”。
- 串流协议选择“WebRTC”。
- 当前没有正在运行的 Desktop2Stereo 推流任务。
- Windows 防火墙允许 Desktop2Stereo、FFmpeg 和 MediaMTX 访问专用网络。
- WebRTC 端口及其后一个端口没有被其他程序占用。
- 头显浏览器支持 WebRTC，建议使用当前版本的 Pico Browser、Meta Quest Browser 或 Wolvic。

默认端口如下：

| 用途 | 默认地址 |
|---|---|
| WebRTC 播放 | `http://电脑IP:1122/live/` |
| 自动校准页面 | `http://电脑IP:1123/` |

校准页面端口始终为“串流端口 + 1”。例如串流端口设置为 `1200`，校准页面端口就是 `1201`。串流端口不能设置为 `65535`。

## 3. GUI 控件说明

选择“高级网络推流”或“GPU 推流”后，网络设置区域会显示以下控件：

| 控件 | 作用 |
|---|---|
| 传输配置：自动校准 | 使用已经保存且仍然有效的校准 FPS 和码率。 |
| 传输配置：手动设置 | 不使用已保存的校准码率，恢复程序的动态码率计算。 |
| 开始校准 | 启动一次新的端到端校准。 |
| 尚未校准 | 当前没有可用的校准记录。 |
| `30 FPS · 30 Mbps` 等绿色文字 | 当前配置与校准记录匹配，可以使用。 |
| 配置已过期 | 影响性能的配置已经改变，需要重新校准。 |

“自动校准”表示使用校准结果，不代表每次启动推流都会重新测试。只有点击“开始校准”才会执行新的测试。

## 4. 快速操作步骤

1. 完全停止当前运行任务。
2. 将“运行模式”设置为“高级网络推流”或“GPU 推流”。
3. 将“串流协议”设置为“WebRTC”。
4. 将“传输配置”设置为“自动校准”。
5. 点击“开始校准”。
6. 等待电脑端弹出“自动网络与性能校准”窗口。
7. 戴上头显，在头显浏览器中输入弹窗显示的地址，例如 `http://192.168.31.199:1123/`。
8. 保持校准页面位于前台，不要锁屏、切换标签页或退出浏览器。
9. 等待各档位测试完成。切换档位时画面短暂中断、页面显示重新连接属于正常现象。
10. 看到“校准完成”和推荐配置后，点击“关闭”。
11. 使用正常的 WebRTC 播放地址打开串流，例如 `http://192.168.31.199:1122/live/`，进行最终画面确认。

校准期间程序会临时把目标 FPS 切换为“自动”。校准成功后会改为选出的 FPS；取消、启动失败或进程中止时会恢复校准前的目标 FPS。

## 5. 校准过程说明

程序从低到高测试当前设备能够覆盖的档位：

```text
30 → 40 → 48 → 50 → 60 FPS
```

每个档位至少测试约 10 秒，从头显开始回传有效统计数据后计时。实际总时长通常为 40～90 秒，取决于能够测试的档位数量以及是否触发码率重试。

每次测试会观察：

- 电脑端 SBS 实际生成 FPS。
- 提交给 FFmpeg 的实际 FPS。
- CUDA 到 CPU 画面转换耗时。
- FFmpeg 帧提交耗时。
- 头显端 WebRTC 解码 FPS。
- 丢帧、冻结、RTP 丢包。
- 抖动缓冲时间和实际接收码率。
- 接收到的视频宽度和高度。

如果电脑端能稳定产生当前 FPS，但头显接收不稳定，程序会把当前档位目标码率降到原来的约 75%，重新测试一次。重试仍不稳定时，会停止继续升档并回退到已经通过的最高档位。

当前稳定性判定要求包括：

- 至少收到 5 个头显统计样本。
- 发送 FPS 达到目标的 95% 以上。
- 解码 FPS 达到目标的 92% 以上。
- 丢帧比例不超过 1%。
- 测试窗口内没有冻结。
- RTP 丢包和抖动缓冲处于允许范围。

如果没有任何档位完整通过，程序仍会选择最低安全档，并将结果标记为受限。

## 6. 如何查看和使用结果

校准成功后，GUI 会显示类似：

```text
48 FPS · 48 Mbps
```

程序会保存以下设置：

| 配置项 | 含义 |
|---|---|
| `Target FPS` | 校准选出的发送帧率。 |
| `Use Stream Calibration` | 是否使用校准配置。 |
| `Stream Target Bitrate Mbps` | FFmpeg 目标码率。 |
| `Stream Peak Bitrate Mbps` | FFmpeg 峰值码率和缓冲预算。 |
| `CRF` | 根据校准后的安全目标码率自动选择的恒定质量值：30 Mbps 及以上为 20，25-29 为 23，21-24 为 26，19-20 为 28，低于 19 为 30。 |
| `Stream Calibration Port` | 头显校准页面端口。 |

运行状态和最终结果保存在：

```text
src/desktop2stereo/logs/stream_calibration_state.json
src/desktop2stereo/logs/stream_calibration_profile.json
```

普通用户不需要手动修改这两个文件。排查问题时可以用它们确认当前测试档位、发送 FPS、头显样本数量和最后一次校准结果。

## 7. 哪些变化会使校准结果失效

校准记录与以下配置绑定：

- 计算设备。
- XR 头显型号。
- 立体显示模式，例如 Half-SBS 或 Full-SBS。
- 深度模型。
- 深度处理分辨率。
- 画面捕获工具。
- 视频编码器后端。
- 串流协议。

其中任意一项变化后，GUI 会显示“配置已过期”。此时仍可手动推流，但建议在最终使用环境中重新校准。

以下情况也建议重新校准：

- 更换路由器、Wi-Fi 频段或头显连接位置。
- 更换 Pico、Quest 或其他头显。
- 更换头显浏览器，或者 Wolvic 在 Gecko 与 Chromium 版本之间切换。
- 浏览器或头显系统完成较大版本升级。
- 改变输出分辨率、编码格式或画质设置。
- 电脑 GPU、驱动或性能模式发生变化。

## 8. Pico、Quest 与 Wolvic 的帧率说明

Pico Browser、Meta Quest Browser 和 Wolvic 没有统一的“视频最高只能播放 30 FPS”规则。实际能力会受到头显型号、浏览器内核、视频分辨率、H.264/H.265 解码能力、码率、无线网络和系统负载影响。因此程序不会对所有头显全局锁定 30 FPS，而是从 30 FPS 起逐档测试。

当前版本主要使用 WebRTC `framesDecoded` 统计头显成功解码的帧率。它不一定完全等于最终呈现到屏幕上的帧率。如果校准选择了 40 FPS 以上，但肉眼观察仍像 30 FPS，或者运动画面存在稳定的周期性顿挫，请执行以下操作：

1. 把“传输配置”切换为“手动”。
2. 将目标 FPS 手动设为 30。
3. 对比 30 FPS 与校准结果的流畅度、延迟和稳定性。
4. 保留更稳定的配置，并记录头显型号、浏览器名称和版本。

后续校准版本可进一步加入实际呈现帧率统计，以区分“已经解码”和“已经显示”。

## 9. 取消校准

点击校准窗口中的“取消校准”会：

- 停止当前推流进程。
- 关闭校准窗口。
- 恢复开始校准之前的目标 FPS。
- 保留上一次成功的校准记录，不用未完成结果覆盖它。

也可以点击主窗口的“停止”。如果校准尚未完成，程序同样会恢复校准前设置。

## 10. 常见问题

### 10.1 看不到“开始校准”按钮

确认运行模式是“高级网络推流”或“GPU 推流”。“MJPEG 串流”不会显示该控件。

### 10.2 提示自动校准需要 WebRTC

把“串流协议”改为“WebRTC”。RTMP、RTSP、HLS 和 SRT 不使用浏览器端 WHEP 反馈页，不能运行当前闭环校准。

### 10.3 头显打不开校准地址

依次检查：

1. 电脑和头显是否在同一局域网。
2. 输入的是弹窗中的局域网地址，而不是 `127.0.0.1`。
3. 校准进程是否仍在运行。
4. Windows 网络类型是否为“专用网络”。
5. 防火墙是否允许校准端口和 WebRTC 端口。
6. 是否有其他程序占用了“串流端口 + 1”。

### 10.4 页面显示等待测试流或 WHEP 错误

校准刚启动或切换测试档位时，FFmpeg 会重启，头显页面会自动重连。短暂等待属于正常情况。如果持续超过 15 秒：

- 检查电脑日志中 MediaMTX 是否成功启动。
- 检查是否出现 `no stream is available on path 'live'`。
- 检查 FFmpeg 是否成功选择 H.264/H.265 编码器。
- 检查音频采集异常是否已经自动降级为静音，而不是导致 FFmpeg 停止。

### 10.5 校准页面反复重连

每次切换 FPS 或码率都会重启 FFmpeg，因而会发生一次正常重连。持续反复重连通常表示：

- FFmpeg 发布失败。
- MediaMTX 内部 RTSP 发布超时。
- 编码器无法处理当前分辨率或帧率。
- 端口被占用。
- 头显浏览器与当前编码格式不兼容。

### 10.6 校准结果只有 30 FPS

这不一定表示头显浏览器固定限制为 30 FPS。可能的瓶颈包括：

- 电脑端立体生成速度不足。
- 4K 编码负载过高。
- Wi-Fi 带宽、抖动或丢包。
- 头显硬件解码不足。
- 浏览器后台降频。
- 浏览器只能稳定解码当前分辨率下的 30 FPS。

保持头显页面在前台、靠近路由器，并分别测试较低分辨率和较低码率，可以进一步定位瓶颈。

### 10.7 校准后正常播放仍卡顿或花屏

- 确认 GUI 显示的校准记录没有失效。
- 确认播放使用 WebRTC 地址，而不是直接打开内部 RTSP 地址。
- 尝试手动降低到下一个 FPS 档位。
- 将目标码率再降低 20%～25%。
- 检查 MediaMTX 是否出现 `reader is too slow`。
- 检查头显是否通过 UDP ICE 连接；TCP 可以回退使用，但更容易受到队头阻塞影响。

## 11. 推荐的校准环境

为了让结果代表实际使用条件：

- 在平时使用头显的位置进行校准。
- 使用最终准备长期使用的浏览器。
- 校准时关闭头显后台下载、系统更新和其他串流应用。
- 电脑保持最终使用的电源计划、GPU 驱动和性能设置。
- 使用与实际运行相同的深度模型、分辨率和 SBS 模式。
- 校准完成后至少播放 3～5 分钟高速运动画面，确认没有持续卡顿、马赛克或音画不同步。

自动校准用于快速找到稳定起点。最终配置仍应以真实头显中的长时间播放效果为准。
